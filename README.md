# Say Clear · 说清楚

描述 Web 应用现状与新迭代的本地系统设计工作台，使用 **Tauri 2 + React + TypeScript + Rust**。桌面版使用系统 WebView，不捆绑 Chromium 或 Node.js 运行时。

打开应用或选择任意系统、子系统、功能模块，直接进入对应的系统图。通过画板右下角 AI 浮球对话并修改当前图。旧版需求对话和需求文档界面已移除；旧工作区中的历史内容继续保留，读取与保存不会清除它们。

## 开始开发

需要 Node.js 24 LTS、npm 11、Rust stable，以及平台原生构建工具。macOS 使用 Xcode Command Line Tools；Windows 需要 Microsoft C++ Build Tools 与 WebView2，Linux 需要 WebKitGTK 等依赖，详见 [Tauri 前置依赖](https://v2.tauri.app/start/prerequisites/)。

```bash
# 首次安装 Rust，已有 Rust 可跳过
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

npm ci
npm run dev
```

项目脚本自动把标准 Rust 安装目录 `~/.cargo/bin` 加入子进程的 PATH，无须修改终端配置。首次构建会下载并编译 Rust 依赖，后续使用增量编译。npm 与 Cargo 依赖分别由 `package-lock.json`、`src-tauri/Cargo.lock` 锁定。

## 功能

- AI 浮球：在当前画板创建或继续 Codex / Qoder CLI 会话，讨论设计或自动修改组件与连线。结果经过场景与图结构校验，共用自动保存、撤销和重做；支持停止请求和新建会话。
- 右键画板组件或连线，选择“加入 AI 对话”，自动打开助手并添加可移除的上下文标签；可累积引用多个对象，保留已输入文字。发送时附带对象详情及连线两端信息，引用随消息保留；未发送引用按工具、画板及版本隔离并保存，支持重启恢复。键盘聚焦对象后也可用 Shift + F10 打开菜单。
- 设置 → AI 设置：选择工具，分别保存命令路径与可选模型，检测本机安装。沿用 CLI 的登录配置，无需在工作区保存密钥。
- 系统图工作台：应用系统结构树与完整宽度的画板；顶部“画板概览”悬停展开说明，支持键盘聚焦或点击展开、Esc 收起。点击组件或连接时，详情从右侧滑出，不挤压画布；关闭详情或点击画板空白处收起。
- 迭代管理：从侧栏统一查看各画板的进行中迭代与历史现状，搜索迭代或画板并按系统筛选，创建、改名、查看变更、完成或放弃迭代。
- Git：工作空间可关联本地代码仓库并选择默认基准分支；从画板或迭代管理创建迭代时同步拉出独立分支，保存仓库、分支及起点提交，历史现状保留关联。
- 组件设置：按自定义场景管理组件模板、输入输出和自定义属性；每张画板选择场景，只能使用该场景的组件，导入、复制及撤销重做遵循相同约束。
- 侧栏设置入口：左侧设置菜单、右侧工作空间设置，支持查看结构数量、保存状态和重新读取本地数据；返回后保留当前画板、选中组件和撤销历史。
- 工作空间设置支持选择本地空文件夹作为数据目录：先保存并复制现有数据，再切换读写位置；保留原目录副本，重启后继续使用新目录。
- 用应用、聚合图、原子图组织可继续嵌套的画板树；支持归属编辑、子图聚合、JSON 预览与搜索。每张图有唯一归属，跨应用通过公开入口引用。
- 各级节点分别保存独立系统图，改名保留稳定 ID、画板与历史内容；侧栏显示组件数量。
- 系统图画板：抽象组件、输入输出端口、四类关系连线、属性编辑、归属、上下游追踪、拖拽缩放、自动布局、撤销重做与 JSON 导入。
- 多图组合视图：点击画板工具栏“组合视图”，在同一画布展开当前版本的引用与被引用画板，跨应用查看完整链路；支持搜索定位、上下游追踪、缩放平移及打开对应版本的原图。现状、迭代、固定历史分别展示，历史快照按需读取，失效与变化的引用保留提示。组合视图只读，不改动原图与归属。
- 大图分级展示：缩小时显示画板总览和汇总引用，点击画板或搜索组件后放大查看；中等缩放显示简洁组件，继续放大显示端口、校验和连线名称。组件与连线按视口加载，搜索始终覆盖完整组合，结果每次展开 100 项。
- 系统名称右侧支持删除；确认后清理系统目录及所有下级内容，删除最后一个系统后保留空工作区。
- 每个系统使用独立目录，根目录 `architecture.json` 是名称、说明和层级的唯一来源。
- 系统图 JSON 预览、原生剪贴板复制、校验导入与撤销。
- 图与变更交付包：按当前画板、当前系统或整个工作区导出文件夹 / ZIP；包含完整 Markdown 变更、离线 HTML 图、版本化 JSON 清单、快照、引用依赖和交接模板。
- Rust 本地保存、串行写入、临时文件原子替换与重启恢复。
- 关闭窗口和退出应用前等待已提交的保存；保存失败时保留窗口供用户重试。
- 首次启动自动复制经过校验的旧 Electron 工作区，保留原文件。
- 支持中文输入法；⌘/Ctrl + K 搜索系统、子系统和模块；画板支持撤销、重做、删除和适应视图快捷键。

## 图与变更导出

点击工作区右上角“导出”，先选择“完整导出”或“变更导出”，再选择当前画板、当前系统（含全部下级画板）或整个工作区。完整导出默认附带历史现状；可以关闭以只交付现状与进行中迭代。桌面版支持文件夹与 ZIP，浏览器预览下载 ZIP。文件夹模式选择父目录后创建独立目录，保留已有导出；ZIP 通过原生保存对话框选择文件，采用原子写入。

HTML 默认显示变更叠加图：新增为绿色、修改为琥珀色、删除为红色虚线，并附文字状态。删除对象和连接保留在图中，未变更上下文可淡化；点击图上的对象或变更清单，可定位并查看可读的字段前后值。现状、迭代和历史版本各自保留完整图，历史差异标记为区间对比，不与进行中变更混算。

变更导出以所选范围内的进行中业务变更为起点，生成相关组合视图，并附各变更所属的完整原图（包括原子图）。组合图截取变更对象、连接前后端点、一跳相邻对象、组件归属链、画板祖先和关联引用，区分实际变更与上下文。对于发生变更的原子图，纳入其精确版本的公开入口、输出和调用方，即使改动发生在内部节点。其他关联画板按到达的组件继续展开，避免带入不相干的引用链。

引用现状、迭代和固定历史分别处理，同一画板的不同版本在组合图中保持独立画框。只加载实际到达的固定历史；即使未选择全部历史，这些引用所需的快照仍随包提供。缺失或失效的来源保留缓存和提示，不替换成其他版本。历史区间不作为变更导出的起点；所选范围没有进行中业务变更时禁用导出并提示切换范围。关联画板自己的独立迭代不计入所选变更。

```text
say-clear-export-<UTC 时间>/
├── README.md               阅读入口、范围、版本与限制
├── changes.md              纳入导出的全部详细变更
├── diagram.html            可离线打开的图，支持搜索、版本切换与缩放
├── manifest.json           格式版本、实际文件路径、画板、版本、引用及提示
├── structure.json          已选画板及必要祖先的结构；graphIncluded 标明有无图
├── catalog.json            场景、组件模板、端口和自定义属性定义
├── combined.json           变更组合视图数据（变更导出）
├── change-context.json     变更起点、精确版本与对象纳入原因（变更导出）
├── boards/<可移植 ID>/
│   ├── README.md           该图的完整组件与连接清单
│   ├── graph.json          活动迭代草稿；没有迭代时为现状
│   ├── baseline.json       活动迭代的固定现状（有迭代时）
│   ├── changes.md          该画板详细变更
│   ├── changes.json        机器可读的迭代差异
│   └── history/            可选历史现状及区间差异
└── templates/
    ├── change-request.md   可复用的实施与验收说明
    └── ai-handoff.md       AI / 系统阅读顺序与交接模板
```

导出格式标识为 `say-clear.export`，`manifest.json` 与变更报告的 `schemaVersion` 为 `1`；图快照沿用模型版本 `2`。清单通过 `mode: all | changes` 区分模式，`changeSelection` 记录起点与扩展范围，画板的 `exportRole` 区分 `changed` 和 `context`。JSON、Markdown 与 HTML 均为 UTF-8。其他系统应先检查格式版本，再从 `manifest.json` 读取路径，通过原始稳定 ID 关联对象。路径名附加稳定指纹，兼容 Windows 保留名与大小写不敏感文件系统，不应直接拼接原始 ID。

`changes.json` 按组件和连接列出新增、修改、删除，保留完整 `before` / `after` 对象；修改还提供字段 `path`（JSON Pointer）、可读标签、前后值及存在标记。端口、属性、引用与校验配置保留原始结构，新增与删除同样有完整定义。与工作台一致，位置移动不计入业务差异，JSON 和 HTML 仍保留布局；`affectedComponentIds` 仅为相邻关联复核提示。

`changes.md` 面向人工评审：修改项只显示发生变化的字段及前后值，新增和删除用业务说明、连接方向、端口与规则描述，不嵌入完整对象或 JSON。HTML 变更详情采用相同阅读方式；完整对象保存在结构化 JSON 文件及原图定义中。

历史保存的是更新前现状，因此历史变更按保存顺序比较相邻快照，最后一份与当前现状比较；存在活动迭代时，当前现状取固定基线，不混入未发布草稿。历史区间可能包含现状直接编辑，不是逐次操作日志，也不能恢复放弃的迭代。没有活动迭代时明确标记无待发布变更，不把所有现状对象当作新增。

跨图引用保留已采用的缓存定义；清单记录来源版本、对应文件及定义变化 / 来源失效提示。完整导出不扩展包外画板；变更导出自动附带上述相关归属与引用画板，并在 `change-context.json` 记录范围及原因。两种模式均不包含聊天记录、AI 设置和工作区仓库配置；版本已有的 Git 关联保留（包括仓库路径）。

生成开始时复制工作区与导出选项，再按需读取历史，防止生成期间混用不同版本；任一所需历史缺失或校验失败会阻止生成不完整交付包。导出不修改工作区，关闭窗口会等待正在进行的导出写入。文件数量上限为 10,000，单文件上限 64 MiB，总正文上限 256 MiB；ZIP 使用无压缩存储，不依赖额外运行时。

`npm run test:export` 验证真实桌面中的两种模式、无变更空状态、取消、三种范围、历史快照、变更组合及原子图、文件夹与 ZIP 交付、文件清单及导出前后数据不变。`node scripts/preview-export-changes.mjs <已有导出包目录>` 可从已有包生成新版完整 / 变更 HTML 与 ZIP 样例，来源目录保持只读。

## 数据与迁移

工作区磁盘索引升级为 `schemaVersion: 3`（前端工作区和画板模型仍为版本 2），默认位于 `app_data_dir()/workspace.json`：

- macOS：`~/Library/Application Support/com.sayclear.desktop/`
- Windows：`%APPDATA%/com.sayclear.desktop/`
- Linux：`$XDG_DATA_HOME/com.sayclear.desktop/`，默认 `~/.local/share/com.sayclear.desktop/`

在“设置 → 工作空间设置 → 数据目录”点击“选择文件夹”，通过原生对话框选择一个空文件夹。更换前会等待并保存当前工作区，复制 `workspace.json`、整个 `systems/`（包括附件）以及旧版迁移备份，校验后才切换。原目录保留副本，不再接收后续修改。目录选择保存在默认应用目录的 `data-directory.json`，不会随业务数据复制；以后启动按该配置读取新目录。已有文件的目录及当前数据目录的子目录不能作为迁移目标。

取消选择保持当前目录；复制、校验或配置保存失败时继续使用原目录，未完成的复制不会切换数据源。若进程在复制期间中断，原目录仍保留数据，目标目录可能留下临时或已复制文件。自定义目录不可用或索引缺失时显示错误，连接存储设备或恢复文件夹后重新读取；不会自动创建空工作区或回退到旧副本。符号链接及特殊文件不参与迁移，遇到时提示错误。浏览器预览仅使用浏览器存储，选择本地文件夹需在桌面版操作。

```text
com.sayclear.desktop/
├── workspace.json                 # v3：系统 ID、当前选中节点、组件库
├── workspace-v1.backup.json        # v1 原始备份（如有）
├── migration-v2-backup/            # 拆分前的索引、架构和 content.json 原始备份
└── systems/<系统 ID>/
    ├── architecture.json          # 画板组成树（版本 2）
    ├── index.json                 # 画板 ID，包括脱离架构后保留的内容
    └── boards/<画板 ID>/
        ├── index.json             # 节点内容、活动迭代 ID、历史摘要
        ├── current.json           # 当前现状；迭代编辑时保持不变
        ├── iterations/<迭代 ID>.json # 迭代名称、基线引用、可编辑草稿
        └── versions/<版本 ID>.json  # 只读基线 / 历史快照
```

系统目录使用稳定 ID，不随名称改变。架构文件的数组顺序就是展示顺序，层级通过稳定的 `parentId` 表达；同级名称和全部节点 ID 必须唯一。不同应用系统可以同名，其数据按 ID 隔离。一个系统的 `architecture.json` 示例：

```json
{
  "schemaVersion": 2,
  "id": "crm-system",
  "kind": "application",
  "name": "客户应用",
  "description": "统一管理客户和销售业务",
  "createdAt": "2026-10-31T00:00:00.000Z",
  "updatedAt": "2026-10-31T00:00:00.000Z",
  "boards": [
    {
      "id": "sales",
      "kind": "aggregate",
      "parentId": "crm-system",
      "name": "销售管理",
      "description": "跟进销售机会"
    },
    {
      "id": "leads",
      "kind": "atomic",
      "parentId": "sales",
      "name": "销售线索",
      "description": "录入与分配客户线索"
    }
  ]
}
```

节点 ID 只能包含字母、数字、连字符和下划线，最长 80 字符；名称最长 80 字符，说明最长 10000 字符。每个根图最多 2000 张下级画板，不固定业务层数；原子图不能包含子图，归属不能形成循环，应用边界不能嵌套。系统说明是架构元数据；后续修改说明不会覆盖独立保存的系统图或历史节点内容。

空工作区使用 `systems: []` 和 `activeNodeId: null`；磁盘索引对应 `systemIds: []` 和 `activeNodeId: null`。只有从未保存过工作区时才创建示例，删除全部系统后重启保持空白。

启动时读取并校验索引、各系统架构、节点内容、现状及活动迭代；历史只读取摘要，不加载快照正文，再由架构生成导航与编辑表单。表单提交经过同一套结构校验后保存为 JSON。手动修改文件后可点击顶部“重新读取本地数据”；外部修改与应用保存冲突时会阻止覆盖并提示重新读取。重新读取会替换当前内存内容，因此界面会提醒保存失败的修改可能丢失。手动新增的架构节点显示空白画板，并保留兼容旧格式的空白内容字段；移除结构节点会保留对应的原系统图与历史内容，使用原 ID 恢复节点即可重新关联。架构损坏、内容文件缺失或版本不支持时显示错误并保留文件。

应用系统名称右侧的删除按钮会先展示系统名称以及下级画板、系统图、组件和连接数量。确认后先保存当前修改，再通过专用删除命令更新索引并递归删除 `systems/<系统 ID>/` 整个目录。删除范围包含架构、内容以及用户放入该系统目录的其他文件；迁移备份和目录外的导出文件独立保留。该操作不能在应用中撤销。删除非当前系统保留选中节点，删除当前系统则选择剩余第一个系统。失败时显示错误；若操作已经进入恢复日志，下次重新读取会继续完成删除。

旧版 Tauri 的 v1 工作区会先备份为 `workspace-v1.backup.json` 再迁移；若当前目录没有索引，则仍支持从旧 Electron 配置目录 `Say Clear/workspace.json` 复制迁移，保持源文件不变。每个旧项目迁移为一个应用系统，原 ID、对话、需求章节、确认状态和修订次数均保留。

首次读取有效的 v2 索引及 `content.json` 时，自动备份到 `migration-v2-backup/` 再拆分文件。原 ID、节点内容、组件库、活动迭代、基线和全部历史都保留；原 `content.json` 也保留但不再读取或更新。迁移前校验旧数据；无效数据、冲突备份或目标文件不会被覆盖。旧 `.pending-workspace.json` 先恢复，再迁移。v1 工作区先沿用旧迁移逻辑，再进入此流程。

前端保存排队，Rust 通过锁串行处理。保存按文件比较规范化后的内容，只写变化的文件；没有变化时不创建事务。编辑迭代只写草稿及有变化的画板元数据，现状和历史保持不变。创建迭代时保存只读基线；完成时更新现状、将同一基线加入历史索引并删除草稿，不再次复制基线。放弃时删除草稿及未进入历史的基线；会话内撤销可重新保存它们。

变化的文件单独暂存到 `.pending-files-*/`；`.pending-files.json` 只记录路径、前后校验值及待删除系统 ID。先校验事务，再原子替换正文、画板索引，最后发布工作区索引。中断后下次读取继续恢复；若目标文件出现外部改动则阻止覆盖。成功后清除恢复记录。单个文件上限仍为 64 MiB，累计工作区及历史不再受 64 MiB 限制。

历史索引包含名称、时间、组件和连接数量及快照校验值。打开历史画板、选择历史引用时按需读取对应文件，显示加载及失败重试状态；前端最多缓存 8 个历史快照，切换目录或重读工作区时清空。历史缺失或损坏不会阻止其他画板启动和普通保存，读取该版本时会报错。修改组件库或迁移数据目录时会逐份校验全部历史，避免破坏未加载版本。

浏览器预览采用 `say-clear.files.v3/` 前缀的独立 localStorage 键，分别保存画板、迭代、历史和索引，并使用只含变更项的恢复日志。首次读取自动迁移原 v1 / v2 工作区键并保留旧键；浏览器容量限制仍然适用，不创建桌面文件。

## 进程边界

前端通过专用命令调用工作区读取、保存、指定历史读取、组件库兼容性校验、指定系统删除、数据目录查询与选择、AI 设置与会话、Markdown 导出、剪贴板写入和平台识别。权限仅授予本地主窗口。前端没有任意路径读写、通用 Shell、远程页面或新窗口权限；数据目录和导出路径由 Rust 打开的系统对话框决定。窗口导航限制在应用本地页面，正式版本使用严格 CSP。

高频交互和未来画板渲染应留在 WebView 内；文件、模型请求及耗时后台任务通过专用 Tauri 命令接入，避免逐帧 IPC。模型密钥应由原生层独立管理，不能放进前端或工作区 JSON。

## 图业务 CLI

`sayclear` 提供图、组件和连接的查询、新建、修改及删除。命令由 Rust 统一图操作层执行，使用工作区原有的模型校验、增量文件事务与恢复机制。CLI 使用稳定 ID；名称用于展示及搜索。

```bash
# 开发时运行；首次执行会编译 Rust，编译日志在 stderr
npm run cli -- --help
npm run cli -- graph list --json

# 构建独立二进制：src-tauri/target/release/sayclear（Windows 为 .exe）
npm run build:cli
```

下列示例中的 `sayclear` 指构建后的可执行文件。可把它放入 PATH，也可直接使用完整路径。默认读取桌面应用的数据目录设置；`--workspace /绝对路径` 直接指定业务目录，`--data-dir /绝对路径` 从另一配置目录读取 `data-directory.json`，两个选项不能同时使用。相对目录以当前终端目录为基准。

```bash
sayclear graph list --json
sayclear graph list --query 注册 --json
sayclear graph get GRAPH_ID --json
sayclear catalog list --json
sayclear component list --graph GRAPH_ID --json
sayclear connection list --graph GRAPH_ID --json
```

独立二进制的成功结果统一输出至 stdout：`{"ok":true,"result":{...}}`；开发时需要机器读取可使用 `npm --silent run cli -- ...`，避免 npm 自身的脚本提示混入输出。请求与 JSON 输入上限为 8 MiB，查询响应上限为 256 MiB。`result.data` 为查询数据，`result.revision` 为内容版本标识。`graph list` 的每个图条目也带自己的 `revision`；列表顶层版本用于创建根应用系统。版本由图业务内容、结构及组件库计算，与界面选择、历史正文缓存、旧需求文档的 `revision` 无关。

所有写操作必须传 `--if-match REVISION`。创建子图使用父图版本，创建根系统使用图列表顶层版本；其余操作使用目标图版本。版本不匹配时拒绝修改，需要重新查询。`--dry-run` 会完整校验并返回 `wouldChange` 与候选结果，保留磁盘及界面状态。

```bash
# 空工作区可先 graph list 取得版本，再创建根系统
sayclear graph create --id crm --name 客户应用 --if-match LIST_REVISION
sayclear graph create --parent crm --id register --name 用户注册 --kind atomic --if-match PARENT_REVISION

# 修改输入是 JSON 对象，既支持文件也支持标准输入；无需在 shell 中拼接 JSON
sayclear graph update register --input changes.json --if-match GRAPH_REVISION
sayclear component create --graph register --input component.json --if-match GRAPH_REVISION
sayclear component get COMPONENT_ID --graph register
sayclear component update COMPONENT_ID --graph register --input component-changes.json --if-match GRAPH_REVISION
sayclear component delete COMPONENT_ID --graph register --if-match GRAPH_REVISION
sayclear connection create --graph register --input connection.json --if-match GRAPH_REVISION
sayclear connection update CONNECTION_ID --graph register --input connection-changes.json --if-match GRAPH_REVISION
sayclear connection delete CONNECTION_ID --graph register --if-match GRAPH_REVISION
sayclear graph delete register --if-match GRAPH_REVISION --dry-run
```

`component create` 至少提供 `templateId`，可选 `id`、名称、位置、端口及属性；默认类型、端口、说明及属性值来自当前场景模板。`connection create` 至少提供 `sourceId`、`targetId`，默认关系为依赖；数据流必须提供合法输入输出端口。通过 `catalog list` 查看场景、模板和属性定义。更新使用字段补丁，ID、模板类型、跨画板引用和历史不能通过普通属性补丁改写。

`graph update` 支持一次提交多项操作，整批校验、整批保存，任一操作失败均不应用。比如 `changes.json`：

```json
{
  "description": "新增注册成功后的通知",
  "operations": [
    {
      "op": "component.create",
      "value": { "id": "notify", "templateId": "builtin-action", "name": "发送通知" }
    },
    {
      "op": "component.update",
      "id": "notify",
      "changes": { "description": "注册成功后发送通知" }
    },
    {
      "op": "connection.create",
      "value": { "sourceId": "board-entry", "targetId": "notify", "type": "dependency" }
    }
  ]
}
```

新图包含场景中的公开能力入口 `board-entry`。创建子图只创建结构和画板，父图中的引用通过现有引用编辑器管理。`component delete` 同时清理关联连接及子组件归属；被其他画板现状、迭代基线或历史引用的源组件不能直接删除。

删除图要求没有子图，且没有其他内容引用它。子图删除沿用架构编辑器的移除语义：从结构树移出，保留内容及历史，返回 `detached:true, contentRetained:true`；脱离内容的 ID 不能被新图复用。删除无子图的根应用系统通过专用删除事务清理整个系统目录，不能撤销。可先用 `--dry-run` 查看删除结果。

读取默认使用当前可编辑图；`--graph-version current` 读取现状，`--graph-version iteration` 读取活动迭代，`--graph-version history --history VERSION_ID` 读取指定历史。迭代进行中禁止修改只读现状，历史始终只读。CLI 修改保留迭代身份、现状基线及历史快照。

桌面运行时，CLI 经带本机凭据的回环连接提交请求，应用先等待已有保存，再在最新内存状态上执行命令。业务编辑弹窗、设置或工作区切换期间返回 `BUSY`，保留尚未提交的编辑。结果过期时拒绝覆盖；普通图修改进入当前画板的撤销记录，结构创建及移除提供工作区撤销。命令成功表示已经保存。应用关闭时，CLI 持有操作系统工作区锁完成读取、执行及事务提交；桌面使用同一把锁。连接已经发送后超时不会自动离线重放，需先查询实际状态再决定下一步。

退出码：`0` 成功，`2` 参数或输入无效，`3` 对象不存在，`4` 版本冲突，`5` 工作区被占用，`6` 桌面未就绪或连接超时，其他错误为 `1`。错误以 `{"ok":false,"error":{"code":"...","message":"..."}}` 输出至 stderr。`--help` 提供全部参数。内置 AI 对话目前继续使用下述 JSON 改图协议，业务 CLI 可供外部助手及脚本调用。

## AI 对话与设置

先在终端安装并登录 [Codex CLI](https://developers.openai.com/codex/noninteractive) 或 [Qoder CLI](https://docs.qoder.com/zh/cli/overview)，然后在「设置 → AI 设置」选择工具并保存。默认命令为 `codex` / `qodercli`；也支持填写可执行文件的绝对路径（无需引号），以及工具支持的模型名称。检测按钮只检查命令能否运行，账号、网络和模型权限在发送时验证。浏览器预览可查看界面及保存预览设置，实际调用须使用桌面版。

点击画板右下角的 AI 浮球，输入需求并发送。首次发送创建 CLI 会话，后续按明确的会话 ID 继续；「新建会话」开启独立上下文。Enter 发送，Shift + Enter 换行，中文输入法确认不会误发送。每轮只附带当前画板、说明与当前场景的组件定义，CLI 续聊会保留既有会话上下文。会话记录由 CLI 自身管理，界面最近 50 条消息、输入草稿及会话 ID 保存在本机 WebView 存储中，Codex 与 Qoder 各自保留一份会话。切页、切换画板或修改同一工具的模型配置不会隐藏已有会话；再次打开或重启应用后可继续。首次使用新存储时会恢复同一工具已有的旧版非空缓存，优先匹配当前画板；旧记录保留。

普通讨论只返回回复；改图结果校验后自动应用，保留活动迭代、基线和历史，支持画板撤销与重做。历史和只读现状只能讨论。等待期间手动修改画板或组件库，会拒绝过期结果。进入设置或迭代管理页时请求继续；切换画板、离开当前版本或切换 AI 工具时停止本轮并保留会话记录。收起对话框可在当前画板继续操作；「停止」会取消本轮，并阻止迟到结果修改画板。无效结果、登录失败、超时或输出超限均显示错误并保留画板。

Rust 使用参数数组和 stdin 调用 CLI，不拼接 Shell 命令。Codex 使用 `exec --json` 与明确 ID 的 `exec resume`、只读沙箱；Qoder 使用 `--print --output-format json`、`--resume`，关闭内置工具及外部 MCP 加载。工具在独立的 `ai-workdir/` 运行，返回 JSON，由应用校验并提交画板，不直接写业务文件。执行中实时显示会话连接、等待模型、重连与接收回复的阶段及已等待秒数；会话 ID 一旦返回就保存。收到完成事件后立即校验结果，不等待 CLI 的后台清理结束。单轮原生超时为 5 分钟，前端另有 5 分 30 秒 IPC 兜底超时；单个输出上限为 8 MiB。

AI 配置保存在默认应用目录的 `ai-settings.json`，与数据目录选择一样独立于工作区；更换业务数据目录不会更改 AI 工具配置。配置只存工具、路径及模型，不存密钥。首次执行依赖已安装 CLI 的账号授权和网络可用性。

`npm run test:ai` 在隔离数据目录和真实 Tauri WebView 中运行双工具适配测试，使用本地测试 CLI 子进程，无需付费模型。覆盖带空格的命令路径、检测与保存、创建和继续会话、分阶段进度、重连恢复、结果返回后进程未退出、改图、撤销重做、非法模板、工具失败、执行中取消、并发编辑保护、切页与切换画板续聊、工具切换及跨进程恢复；截图保存在 `artifacts/ai-*/`。协议与子进程超时等单元测试包含在 `npm run check` 中。

## 系统图画板

打开应用后直接显示 **系统图**；选择任意系统、子系统或功能模块，切换到它的独立画板。修改共用顶部的本地保存状态。可以从空画板添加组件，也可以载入注册流程示例；已有内容不会被示例覆盖。

- 默认“Web 应用”场景提供角色、能力、交互界面、行为、规则、校验、数据对象、状态、事件、接口、服务、存储 12 类组件。可在“设置 → 组件设置”中定制场景与组件；双击画板组件或在右侧详情中编辑名称、说明、归属、输入输出及已定义的属性。
- 点击或拖动组件右侧的输出端口，再连接到目标的输入端口；工具栏“添加连接”可创建组件整体之间的处理流程、依赖和事件关系。
- 拖动组件调整位置；拖动空白平移，滚轮 / 触控板滚动平移，⌘/Ctrl + 滚轮缩放。工具栏提供缩放、适应画板和自动布局。
- 自动布局优先保留已有行列，整理对齐与间距；整齐的二维布局保持原位。重叠或尚未排列的组件按连接关系布局。迭代中已删除的组件按当前布局避让显示，适应画板包含这些组件，原有基线与历史位置保持不变。运行 `npm run test:layout` 在隔离的真实桌面工作区验证注册迭代、可见节点避让、撤销重做与重启恢复。
- 搜索组件可定位目标；按关系类型筛选，并从组件详情追踪上游来源或下游影响。依赖箭头指向被依赖方。归属显示于组件底部和属性面板，点击归属名称可定位父组件。
- 支持复制组件、删除组件 / 连接、撤销和重做（当前画板会话保留最近 40 步）。组件删除会一并移除关联连接，其子组件回到画板顶层；端口删除会移除连接到该端口的连线。修改端口名称保留连接。
- “JSON”提供结构化预览、复制备份和粘贴导入；导入先校验，成功后替换当前画板，支持撤销。画板获得焦点时支持 ⌘/Ctrl + Z 撤销、⌘/Ctrl + Shift + Z 重做、Delete 删除、Esc 取消连线和 F 适应画板。

### 系统现状与迭代

- 现状：没有迭代时可直接维护；创建迭代后，现状基线只读。
- 本次迭代：编辑本次迭代的系统模型，自动标记节点和连接的新增、修改、删除；删除项以红色虚线保留用于对比。
- 变更清单：按稳定 ID 对比说明、属性、端口、关系端点及条件等字段；位置变化不计为业务变更。直接关联但未修改的组件提示“关联影响”，不当作已修改，也不保证穷尽影响。
- 更新为现状：在确认实际落地后，将本次迭代的结果作为新现状，原基线作为历史快照保留；这只是更新系统模型，不执行真实部署。每个画板最多保留 50 个历史现状，达到上限时阻止继续更新，不静默删除历史。
- 放弃迭代：恢复创建迭代时的现状，可在当前会话撤销。JSON 导入只能修改当前可编辑内容，不能替换现状基线和历史；迭代期间的现状及历史视图禁止编辑。
- 看能力／看流程／看实现：突出显示当前视角的对象，其他对象作为背景保留。

空白画板可点击“体验「手机号注册」迭代示例”，查看邮箱注册的现状，以及增加手机号注册、接入短信平台、替换注册欢迎页的迭代。 已构建桌面 debug 版本后，也可运行 `npm run preview:iteration`，直接打开独立的示例工作区；示例及后续修改保存在 `artifacts/iteration-preview-*/`。所有快照与迭代随工作区保存，前端与 Rust 同时检查其结构、关系和模板引用。

这一版迭代以单张画板为范围。同一画板内跨版本保留对象 ID；支持跨画板引用；系统级统一迭代、并行迭代与部分合并尚未实现。

侧栏“迭代管理”汇总工作空间内各画板的进行中迭代、待落地变更数量和历史快照。支持按迭代名称或画板路径搜索、按系统筛选；可以直接为没有活动迭代的画板创建迭代，包括空画板。改名保留迭代 ID、开始时间、现状基线和当前变更。变更清单展示组件与连接的增删改及字段对比，可跳转到对应迭代画板。

“完成迭代”确认后更新目标画板现状，更新前快照进入“历史现状”，打开后只读查看。没有业务变更或已达到 50 个历史快照时禁止完成。“放弃迭代”确认后恢复原基线；管理页内的放弃不支持撤销。管理页修改当前画板迭代时会清空该画板旧的会话撤销记录，避免撤销恢复已结束的迭代。只打开管理页再返回不会清空画板状态。管理页操作使用拆分存储、串行保存、保存失败重试及重启恢复；已从架构移除的画板内容不参与列表。

运行 `npm run test:iteration-management` 在独立桌面工作区验证搜索筛选、创建与改名、变更查看、完成与放弃、画板跳转、历史只读和跨进程恢复。截图、工作区快照及结果保存在 `artifacts/iteration-management-*/`。

运行 `npm run test:iteration` 在隔离的真实 Tauri 桌面工作区验证 12 种组件、编辑与只读保护、自动对比、更新现状、放弃与撤销、历史查看及跨进程恢复。截图与测试工作区保留在 `artifacts/web-app-iteration-*/`，不会修改日常工作区。

### Git 仓库与迭代分支

在桌面版“设置 → 工作空间设置 → Git 仓库”直接填写本地路径、HTTPS 或 SSH 仓库地址，也可通过文件夹选择器选择已有仓库。填写本地路径后点击“读取仓库”；填写远程地址后点击“克隆并读取分支”，再设置默认基准分支并保存关联。本机需安装 Git，仓库至少包含一次提交；支持 `~/` 路径、从子目录识别仓库根目录以及关联 Git worktree。输入新地址后会重新校验，读取失败时保留已保存的关联。

远程仓库保存在应用默认数据目录的 `git-repositories/` 中；再次读取同一地址会复用已有克隆，后续同步可通过 Git 命令完成。仓库 URL 与实际本地路径分别显示和保存。克隆沿用本机 Git 凭据与 SSH 配置，HTTPS 地址使用凭据管理器，不接受在 URL 中直接嵌入用户名或令牌。仓库关联适用于整个工作空间，随工作空间数据保存；更换工作空间数据目录时，克隆仓库继续使用原位置。

从画板或“迭代管理”创建迭代时，会同时创建独立的本地 Git 分支。可修改自动生成的 `iteration/…` 分支名，并选择本次迭代的基准分支；创建成功后保存仓库路径、分支名、基准分支与准确的起点提交。重复分支名、失效基准分支或仓库不可用时显示错误并保留创建表单；保存迭代失败时撤回本次新建且未被其他进程修改的分支。

创建分支后，代码目录保持当前检出的分支，已有文件修改继续保留。迭代改名保留原分支；完成或放弃迭代后保留 Git 分支，完成后的历史现状继续显示分支关联。Git 提交、切换、合并和推送由代码开发流程管理。解除或更换仓库关联只影响以后创建的迭代，已有迭代和历史保留原仓库信息。未关联仓库时，创建迭代沿用本地画板流程。

运行 `npm run test:git`，在隔离工作空间和临时 Git 仓库中验证真实桌面流程；截图与结果保存在 `artifacts/git-*/`。

### 场景与组件元数据

“校验”组件内按列表顺序维护最多 32 条规则，每条规则包含名称、判断条件、适用条件和失败提示，支持上移、下移和删除。整体通过条件可选“全部满足（AND）”或“任一满足（OR）”；检查方式可选检查全部并汇总结果，或结果确定即停止（AND 首条失败停止，OR 首条通过停止）。适用条件留空表示始终检查，不满足时跳过；空规则列表或没有适用规则时不通过。这里描述业务设计，不实际执行条件表达式。

默认 Web 应用组件库提供“校验”模板及“通过 / 不通过”两个输出，画布显示规则数量、前三条规则顺序、通过条件和检查方式，右侧详情展示全部规则。已有自定义组件库可在“组件设置”中新建模板，基础类型选择“校验”，并设置所需的输入输出。配置保存在组件的 `validation` 字段中，数组顺序就是检查顺序；保存、导入、撤销重做、迭代、历史和跨画板引用都保留该配置。规则或策略改变会出现在迭代差异中，并提醒引用方更新。

运行 `npm run test:validation` 在独立应用标识、WebDriver 端口和临时工作区中验证规则编辑与排序、策略切换、双出口连线、非法导入拦截、撤销重做、迭代历史和重启恢复。截图及结果保留在 `artifacts/validation-*/`。

在“设置 → 组件设置”中新建场景（如业务流程、数据架构），再添加组件模板。模板可配置名称、基础类型、说明、默认输入输出端口，以及最多 32 个自定义属性。属性支持文本、数字、是 / 否，可以设置必填与默认值。每个场景最多 100 个模板，工作区最多 50 个场景。

画板顶部选择场景，“添加组件”菜单仅展示该场景的模板。实例的模板类型不可在画板中随意更改，名称、说明和端口可按具体职责调整；属性只能填写模板已定义的字段。模板说明和端口的修改只影响之后添加的组件；属性定义立即生效，实例未保存的属性值使用定义的默认值。历史快照保留对象值，属性名称等展示定义仍取自当前模板。模板 ID、场景 ID 和属性 ID 在改名后保持稳定。

切换场景时会校验已有组件；若不兼容，保留原场景和内容，可先移除组件或在空画板选择新场景。JSON 导入使用当前画板的场景校验，不能借助导入的场景 ID 切换允许的组件范围。复制、示例、撤销和重做同样检查组件与属性规则。删除或修改配置时检查所有画板、现状基线与历史快照（含架构移除后保留的节点内容），若会使已有画板失效则拒绝保存并提示原因；例如，给已使用的模板新增必填属性时需提供默认值。

配置保存在工作区索引的可选 `componentCatalog.scenarios` 字段中，随串行保存、事务恢复和数据目录迁移持久化。画板通过可选 `scenarioId` 关联场景，组件通过 `templateId` 关联模板，`metadata` 保存属性 ID 到字符串值的映射（数字及布尔值也以字符串保存并按类型校验）。前端和 Rust 均检查场景归属、模板类型、必填项与属性类型。

未自定义组件库时使用内置“Web 应用”组件库。画板必须指定场景，组件必须指定模板。此版是开发阶段的破坏性重构，不读取旧的 v1 画板或旧基础类型，也不自动覆盖原工作区文件。默认场景可以改名及调整模板，不能删除。

### 结构化模型

图本身使用 `schemaVersion: 2`，由 `scenarioId`、`components`、`connections`、`history` 及可选 `iteration` 组成。ID 为稳定唯一标识，不随名称修改。位置与业务字段分开存储，平移和缩放是会话内的查看状态。

| 对象 | 字段                                                          | 含义                                                                     |
| ---- | ------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 组件 | `id`, `type`, `templateId`, `boundary`, `name`, `description` | 唯一身份、语义类型、模板、内外部边界、名称与职责                         |
| 组件 | `inputs`, `outputs`                                           | 输入、输出端口数组；每个端口包含 `id`, `name`, `dataType`, `description` |
| 组件 | `ownerId`                                                     | 同一画板中的父组件 ID；`null` 表示属于当前系统 / 功能节点，归属不能循环  |
| 组件 | `position`                                                    | 画板坐标 `{ x, y }`                                                      |
| 连接 | `id`, `name`, `type`, `description`                           | 身份、名称、关系类型与语义说明                                           |
| 连接 | `sourceId`, `targetId`                                        | 起点、终点组件 ID，方向由起点指向终点                                    |
| 连接 | `sourcePortId`, `targetPortId`                                | 起点输出、终点输入端口 ID；组件整体关系允许 `null`，数据流必须指定端口   |
| 连接 | `protocol`, `condition`                                       | 传输方式 / 协议与触发条件；字段映射、异常处理写入说明                    |

连接类型为 `data`（数据流）、`control`（执行顺序）、`dependency`（依赖）、`event`（事件传递）、`contains`（组成）、`calls`（调用）、`implements`（实现）、`reads`（读取）、`writes`（写入）、`constrains`（约束）、`transitions`（状态迁移）。允许不同组件之间的循环流转；不允许自身连线、本图连线端点悬空、归属环、同类型同端点重复连线。端口数据类型是描述信息，不自动执行类型转换或推断兼容性。

每张图最多 300 个组件、1200 条连接；每个组件最多 32 个输入和 32 个输出端口。前端 Zod 与 Rust 均校验格式及引用。共享样本位于 `tests/fixtures/diagram-v2.json`，数据定义和图操作位于 `src/shared/diagram.ts`，原生校验位于 `src-tauri/src/diagram.rs`。

### 持久化与边界

系统图按画板保存到 `systems/<系统 ID>/boards/<画板 ID>/`，现状、活动迭代和历史为独立文件；不改变 `architecture.json` 的层级定义，也不增加需求文档修订次数。没有系统图数据的旧节点显示空画板。内存中的 `history` 可只含摘要，读取历史时通过 `load_history` 获取完整快照。具体格式及迁移见“数据与迁移”。

画板表示设计信息，不执行处理逻辑或访问真实数据库。目前归属采用标签和属性表达，尚不支持嵌套容器展开 / 折叠、跨画板直接连线、多人协作和历史版本一键回滚。撤销历史在切换节点或重新读取数据后清空。

## 跨画板引用

在来源图中编辑组件，勾选“允许其他画板引用”；在使用方点击“引用画板”，选择来源、版本和入口。引用保留能力、事件、接口等原始类型，可把来源公开的事件、数据或接口附带为输出端口，再与本图流程连接。引用不会执行远程调用，也不会递归展开来源图。

默认引用来源的现状；来源正在迭代时，现状取其基线。显式选择迭代会绑定具体迭代 ID，并显示“迭代中”。迭代发布或放弃后需重新选择现状，不自动改绑下一次迭代。当前示例中“注册成功”仍处于注册迭代，因此账户初始化图明确引用该迭代。

引用保存已采用的定义快照。来源名称、说明、端口、属性或公开输出变化时，节点及相关连接提示待检查；点击“更新引用”预览最新定义和将移除的连接，再保存。位置变更不算契约变更，引用更新保持本地 ID、位置与归属。更新可撤销，现状基线和历史中的定义不会被覆盖。缺失来源或取消开放是可修复状态，仍保留原定义与连线供检查，不阻止工作区打开。

点击引用底部的来源或双击引用节点可跳转；顶部“返回”回到来处。“被引用”及组件详情列出当前现状和活动迭代中的使用方。已脱离架构的历史内容不作为可选来源，历史快照仍保留引用信息。删除来源系统前会列出受影响的画板。跨场景引用可以使用来源的模板，模板、属性和值仍接受前后端校验；引用组件不能再次对外开放。

运行 `npm run test:references` 验证真实桌面中的添加引用、版本选择、事件端口、来源跳转与返回、来源改名后的显式更新、输出删除告警及跨进程恢复。

### 画板聚合与跨应用引用

在应用或聚合图中“新建子图”，或选中至少两张同级图“聚合子图”。新画板带公开能力入口，可编辑输入、输出与说明。聚合引用现状中的公开入口；缺少入口时需先开放。聚合保留原图 ID、内容、历史和其他画板的引用。上级图已有业务连线保留；无连接的子图卡片替换为聚合引用，具体业务顺序由作者编排。原子图内仍可包含多个组件与条件分支。

“引用画板”可筛选来源应用，选择现状、活动迭代或固定历史版本。公开能力、API、事件等保留其原有业务类型；引用缓存已采用定义，源变化时提示显式更新，源失效时保留缓存和连接并告警。历史版本引用可跳转到只读历史画板。左侧区分“本图有变更”与“下级 N 张图有变更”，只汇总实际迭代差异，不把位置变化或下级修改当成本图修改。

架构文件升级为版本 2，旧固定三层架构不再直接读取；开发期示例在独立工作区转换，原始工作区保留。工作区磁盘索引现为版本 3，画板内容已拆分为独立文件；运行时模型仍为版本 2。

运行 `npm run test:composition` 验证真实桌面中的连续聚合、稳定 ID、跨应用入口、来源跳转、历史只读与重启恢复。已有注册/配置案例可运行 `node scripts/preview-composition.mjs <案例工作区路径>` 生成独立的跨应用预览，来源工作区不改写。
